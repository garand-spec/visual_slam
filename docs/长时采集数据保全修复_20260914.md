# 长时间采集与地图重置后的数据保全修复

日期：2026-09-14。分析基线：47ca023。本次范围为深度归档、位姿关联和既有数据恢复；没有完成工业级定位精度验收或 IMU 标定。

## 已确认的故障

run_20260913_204857 运行约 19.18 分钟，有 24,499 帧。2,000 组深度的时间范围为 3561.297105～4122.845885，而最终位姿只有 4191.877729～4281.675655，两者没有交集。原模型结果为 unavailable。

ORB-SLAM3 的 Tracking::ResetActiveMap 会清除活动地图的关键帧，并将相应历史轨迹标为 lost；最终导出因此不能保留这些帧的优化位姿。适配器又在保存 2,000 组深度后停止归档，导致后段虽有位姿却没有配套深度。原后处理将这一数据关联失败笼统解释为没有可靠深度，提示不准确。

## 修复内容

1. 每组深度与灰度图保存后，将采集当时的 Tcw 平移、四元数、时间戳、地图 ID、地图版本、跟踪支持数和连续片段编号一起写入索引并刷新。地图重置不会删除这些独立归档；主位姿 CSV 缺失时，新索引仍可用于重建。
2. 移除 2,000 组数量截断。持续归档，保留 1 GiB 可用空间；空间不足、写盘错误会写入 depth_archive_status.json，并通过模型状态接口提示。该保护不代表可以无限录制，仍需容量规划和归档管理。
3. 最终位姿完整覆盖某个地图版本时使用最终位姿；覆盖不完整时，该版本整体使用可信采集位姿，另分配显示地图编号。不同地图版本不混合，在线位姿与最终位姿不在同一模型中混合。
4. 旧索引没有嵌入位姿时，可从 poses.csv 配对恢复，但必须具有可信跟踪和明确地图版本。无法配对时报告 pose_association_failed，不声称缺少深度。部分写入的 CSV 尾行会跳过，并统计丢弃行数。
5. 模型、模型预览和回放轨迹均保存位姿来源。网页对恢复结果标注“未优化保留”和“采集时位姿”，不会显示为最终优化地图。模型导出成功后才发布对应回放轨迹。
6. 后处理仍有资源上限：默认最多抽取 500 组深度，按地图分配采样，在各组时间范围内均匀取样；根据输入量调整像素采样步长，控制输入顶点预算。采样上限限制模型细节，不再限制原始深度继续归档。

文件：src/depth_archive.h、src/orbslam3_rervision.cpp、tools/reconstruct_scene.py、tools/pose_viewer.py、web/pose_viewer/app.js。
