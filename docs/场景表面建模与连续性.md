# 场景表面建模与连续性改进

更新日期：2026-09-12。范围：整体静态场景和可见物体表面，不做桌椅语义分割。

## 已实现

采集时保存通过左右视差一致性检查的双目深度和校正灰度图。正常结束后，等待回环、全局优化和局部建图线程停止，按最终关键帧关系重新计算可信相机位姿，再在后台生成三角网格。网页支持旋转查看、选择地图和下载 PLY、OBJ。

重建用深度图中相邻有效像素形成三角面，拒绝跨深度突变、无效像素和过长边；同一地图内按体素合并重复顶点和三角面。不同最终地图各自导出，避免不同原点的场景堆叠。回放使用与模型同坐标的最终位姿。

这是观测表面网格，有空洞和开放边界，不是完整封闭实体，不保证 CAD 或测量精度。相机为灰度成像，PLY 保存灰度顶点色，OBJ 保存几何。看不到的背面不会生成；透明、反光、无纹理或运动物体仍可能缺失或重影。默认 2 cm 融合体素是合并参数，不代表 2 cm 精度。

## 连续性修改及依据

上次佩戴记录 run_20260912_200735 共 2,133 帧、约 110.35 秒，其中 1,803 帧有有效地图支持，约 84.53%。前半段跟踪较好，后半段反复用 3～8 个地图点初始化，最后只导出了活动地图的 4 个点，掩盖了前面建立的地图。

- 双目初始化至少需要 50 个有限、正深度、有效立体对应点，仅有大量角点不能进入正常定位。
- 至少 3 个关键帧的地图进入短时重定位；纯视觉恢复窗口从 3 秒延长到 6 秒，成功匹配内点门槛保持原要求。
- 至少 50 个地图支持特征、2 个关键帧、连续 5 帧稳定后才投递深度，失效时停止投递。
- 在线预览在地图版本变化时另存并清空，防止重置后混合旧坐标。最终表面按最终地图身份融合。
- 稀疏点云优先保留点数最多的存活地图；表面模型可分别保留多个地图。
- 导出前等待优化线程停止，避免一边优化一边读取“最终位姿”。

短时丢失仍会显示断轨，不插值冒充真实位置。延长恢复窗口只增加找回已有地图的机会，不能替代有效双目输入、正确标定或 IMU 外参。

## 使用

设备已编译部署。通常直接启动、走动采集、正常结束：

```bash
cd /home/linaro/projects/visual_slam
./start_slam.sh --no-viewer
./stop_slam.sh
```

同一局域网打开 [三维查看器](http://192.168.4.124:8765/)。采集时看“实时位置”；结束后进入“历史回放”，等待模型就绪，勾选“显示物体表面模型”。从下拉框选择地图会跳转到对应地图的可信帧。PLY/OBJ 下载完整模型，浏览器最多显示约 80,000 面的简化预览。

先让左右镜头同时看到光照充分、有纹理的静态场景，定位正常后缓慢平移和转向，从不同方向观察物体。仅原地转头无法覆盖各个表面。恢复时尽量重新看向已观察过的区域。

模型构建在停止后异步执行，运行目录中的 model_build.log 是日志，models/status.json 是状态。旧记录没有逐帧深度，不能可靠追溯生成同样的表面模型，需要重新采集。

手工重建新版记录：

```bash
/home/linaro/miniconda3/envs/fire-monitor/bin/python tools/reconstruct_scene.py --run data/runtime/orbslam3/run_YYYYMMDD_HHMMSS
```

主要产物：depth_frames/（深度、灰度、校正参数、索引），optimized_poses.csv（最终原生地图 Tcw），model_poses.csv（保留原始失效与分段信息的回放轨迹），models/scene_map_<id>.ply、.obj、.json。

默认每 6 个稳定跟踪帧尝试投递深度，工作线程只处理最新任务，最多记录 2,000 组。后处理最多均匀抽取 500 组，输入顶点上限 800 万，以限制内存和存储；达到限制后覆盖范围可能不完整。依赖现有 NumPy/OpenCV，不需要额外下载模型或 Open3D。
