# 摄像头三维轨迹可视化

更新：2026-09-12。

## 能做到什么

在同一张有效的 SLAM 地图内，可以展示摄像头的米制相对位置、朝向与轨迹。摄像头固定佩戴时，其运动可以作为佩戴者运动的参考。本层不估计人体骨架、脚的位置或身体中心；转头同样会改变摄像头的位姿。没有重力/外部坐标标定，不能把图中的参考网格当作真实地面，也不能把 Y 数值当作人的高度。

已实现：

- 浏览器三维旋转、缩放、平移、全景、俯视与跟随视角。
- 摄像头示意模型和观察方向视锥；模型尺寸仅用于辨认。
- 历史记录播放、暂停、拖动进度及 0.5×～4× 回放。
- 当前坐标、相对本段起点的位移、朝向变化和轨迹长度。轨迹长度包含估计抖动，不等于真实步行里程。
- 实时位姿快照、采集结束、超时和网络中断状态；跟踪失效时保留最后可信位置并停止连接轨迹。
- 按地图编号和跟踪连续片段分段显示。新数据在采集端记录片段编号，避免浏览器漏掉一次短暂的丢失状态后错误连线。
- 可选显示最多 20,000 个导出点云抽样点。由于在线轨迹未按回环结果重建，点云只作参考，默认关闭。

## 打开和运行

设备在同一局域网中时，打开：

- [三维查看器](http://192.168.4.124:8765/)
- [已有成功记录的回放](http://192.168.4.124:8765/?run=run_20260912_192042)

手动启动查看服务：

```bash
cd /home/linaro/projects/visual_slam
./run_pose_viewer.sh --port 8765
```

它只读取 SLAM 产物，不会自行打开摄像头。实时查看还需另一个终端启动已重新编译的适配器：

```bash
./build_orbslam3_rervision.sh
./run_visual_slam_3d.sh --no-viewer
```

网页选择“实时位置”后会自动跟随最新运行目录。测试或短时采集可用 `--seconds 30`；正常退出使用 Ctrl+C。已有后台 SLAM 可继续使用原来的 `start_slam.sh`、`stop_slam.sh`。

本次启动的查看服务在后台运行，日志为 `logs/pose_viewer.log`，PID 文件为 `logs/pose_viewer.pid`；没有设置开机自启。设备重启后需重新启动查看服务。服务为局域网只读访问，没有摄像头启动、任意文件读取或命令执行接口；默认监听 `0.0.0.0:8765`。仅需本机访问时使用 `--host 127.0.0.1`。

## 数据和坐标约定

实时程序新增 `viewer_state.json`，以临时文件替换方式原子更新，正常处理时最多约 10 Hz。记录 `Twc` 的位置与 xyzw 四元数、相机时间戳、主机更新时间、跟踪状态、地图 ID、受地图支持的特征数、连续片段编号和进程状态。

`poses.csv` 保留原有世界到相机的 `Tcw` 列，追加 `map_id`、`tracked_features`、`source_segment`；每三个处理帧刷新缓冲。回放服务器明确计算 `Twc = inverse(Tcw)`，相机中心为 `-Rcwᵀ tcw`，不能只把平移变号。

显示时对整套世界坐标应用绕 X 轴的 180° 旋转以适配浏览器的显示方向，右侧读数仍为原始 SLAM 地图坐标；这不是重力对齐。网格单位为 1 m，参考平面置于该片段起点下方 0.5 m，位置只是显示约定。

“可信位姿”需要：状态为 `OK/OK_KLT`、数值有限，并且有受地图支持的跟踪特征。旧记录缺少该字段时，保守使用其 `map_points > 0`；旧数据的地图点数可能是每 15 帧更新的缓存。没有地图点的初始化原点不被当作有效定位。

失效帧、采集端片段变化、地图变化、时间倒退、超过 1 秒的间隔或相邻位置超过 2 m 的跳变会切断显示。这两个阈值是保守显示策略，不是人体运动分类器。没有地图编号的旧记录只能尽力分段，不能保证跨段坐标一致。每次显示当前片段，避免把独立地图强行放在一条轨迹上。

实时浏览器每 250 ms 读取快照；生产进程不存在、采集结束或快照超过 3 秒未更新时显示停止/超时，不外推当前位置。实时模式可能跳过帧，其轨迹长度取决于采样；回放可读取完整 CSV。服务对回放文件限制为 128 MiB / 200,000 帧，点云预览限制为 256 MiB。

## 本次实机结果：显示层可用，现场定位尚不稳定

已有 `run_20260912_192042` 的 660 帧记录可以回放，位姿有非零变化；该记录没有真实步行轨迹真值，因此不能证明佩戴者运动测量精度。

本次增加显示层后进行了两次短时实机检查（纯双目、无窗口、关闭稠密融合）：

| 记录 | 处理帧数 | 底层返回 OK 的帧数 | 跟踪特征数大于 0 的帧数（不等于可信帧） | 观察 |
| --- | ---: | ---: | ---: | --- |
| `run_20260912_195419` | 437 | 219 | 2 | 反复初始化与丢失；最终稀疏点为 0 |
| `run_20260912_195559` | 545 | 273 | 8 | 同样频繁丢失，无法保持有效轨迹 |

日志重复出现 `New Map created with 0 points`；大部分帧有数百至上千个图像特征，却没有受地图支持的跟踪点，位姿反复回到初始化原点。这说明当前不足发生在**双目立体对应、深度初始化及持续跟踪链路**。仅凭这些日志，不能把原因确定为某一个参数；还需核对双目有效视场、左右眼顺序、标定与当前图像尺寸，以及立体匹配产生的有效深度数量。

因此：**当前工程有“显示有效轨迹”的能力，但在本次现场输入下，还不能稳定展示佩戴者的真实行走轨迹。**本层会显示失效，不能凭空补出人的位置。进一步限制还有 IMU 外参未完成、缺少外部空间锚点，以及稠密点云未跟随回环重新融合；这些不在本次可视化修改中修复。

上述实机运行用于验证数据通路，随后又增加了“零地图支持不得显示可信位置”和采集端片段编号的保护，并重新编译。最终版本的这两项保护经过独立 C++ 合约测试、Python 测试和浏览器测试，未再次重复相机采集。
